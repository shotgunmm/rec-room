# Calendar Add-On for ExpressionEngine 7

A reusable calendar and events management add-on with a native EE CP interface and a front-end interactive monthly calendar.

---

## Requirements

- ExpressionEngine 7.0.0 or higher
- PHP 8.3+
- MySQL with InnoDB and utf8mb4 support

---

## Installation

1. Copy `system/user/addons/calendar/` to your EE `system/user/addons/` directory.
2. Copy `themes/user/calendar/` to your EE `themes/user/` directory.
3. Log into the EE Control Panel.
4. Go to **Add-Ons** and find **Calendar** in the list.
5. Click **Install**.

EE will create three database tables on install:

- `exp_calendar_events` — event records
- `exp_calendar_settings` — per-site settings (events per list, default 5)
- `exp_calendar_default_content` — per-site weekly events header and description

## Template Tags

### `{exp:event_calendar:events_list}`

Outputs an upcoming events list. Returns no results if no future events exist.

**Parameters**

| Parameter | Default | Description |
|---|---|---|
| `limit` | Site setting (default 5) | Maximum number of events to return |
| `single` | `yes` | `yes`/`no` - include single events |
| `recurring` | `yes` | `yes`/`no` - include recurring events (one row per definition, not per occurrence) |
| `display` | _(unset)_ | `none`, `single`, `recurring` or `both`. Blank/unknown = both. When set, overrides `single=`/`recurring=` (`none` returns no rows). Designed to take a CMS select, e.g. `display="{content:schedule_display}"` |
| `month_scope` | _(unset)_ | `yes` expands recurring events to every occurrence inside the filtered month (same as the calendar's month navigation), one row per occurrence. Unset: one row per recurring event at its next occurrence |
| `order` | _(unset)_ | `date` sorts rows chronologically by occurrence date, then start time. Only the literal value `date` is recognised — unset (or any other value) uses the legacy order: recurring events first by their stored time of day, then single events by date. The `month_scope` path is always chronological regardless of this parameter |
| `status` | `open` | `open` or `any` |
| `var_prefix` | _(none)_ | Prefix for loop variables, e.g. `var_prefix="ev"` gives `{ev:title}` |
| `detail_url` | _(none)_ | Base URL for event detail links |
| `date_format` | `%F %j, %Y` | EE date format string for date portion |
| `time_format` | `%g:%i %A` | EE date format string for time portion |

**Variables**

| Variable | Output |
|---|---|
| `{event_id}` | Integer event ID |
| `{title}` | Event title (HTML-escaped) |
| `{description}` | Event description (formatted with `auto_typography()`, wrapped in `<p>` tags — do not nest inside another block element) |
| `{start_time}` | Formatted start datetime |
| `{end_time}` | Formatted end datetime |
| `{start_date}` | Start date as `YYYY-MM-DD` |
| `{start_time_raw}` | UTC Unix timestamp for start |
| `{end_time_raw}` | UTC Unix timestamp for end |

**Example**

```html
{exp:event_calendar:events_list limit="3"}
    <article>
        <h2>{title}</h2>
        {description}
        <p>{start_time} &ndash; {end_time}</p>
    </article>
{/exp:event_calendar:events_list}
```

### `{exp:event_calendar:display}`

Outputs the interactive monthly calendar. Renders a `<script>` block with `window.CalendarData` and loads `calendar.js`. Requires the following HTML structure in your template:

**Parameters**

| Parameter | Default | Description |
|---|---|---|
| `date_format` | `%F %j, %Y` | EE date format string for date portion |
| `time_format` | `%g:%i %A` | EE time format string for time portion |

**Required HTML structure**

```html
{exp:event_calendar:display}

<div data-calendar>
    <div data-calendar-month-label></div>
    <button data-calendar-nav-prev>&#8249;</button>
    <button data-calendar-nav-next>&#8250;</button>
    <div data-calendar-grid></div>
    <div data-calendar-details></div>
</div>
```

**Data attributes**

| Attribute | Element | Purpose |
|---|---|---|
| `data-calendar` | Wrapper | Initialization target |
| `data-calendar-grid` | Container | Day cells rendered here by JS |
| `data-calendar-details` | Panel | Event detail or default content |
| `data-calendar-nav-prev` | Button | Navigate to previous month |
| `data-calendar-nav-next` | Button | Navigate to next month |
| `data-calendar-month-label` | Any | Displays current month and year |
| `data-calendar-day` | Day cell | Generated by JS — do not add manually |

**Day cell state attributes set by JS**

| Attribute | Condition |
|---|---|
| `data-has-events` | One or more events on this day |
| `data-today` | Matches today's date |
| `data-active` | Currently selected day |
| `data-other-month` | Day falls outside current month |
| `data-loading` | Applied to `[data-calendar]` during AJAX fetch |

Style these via CSS attribute selectors, for example:

```css
[data-calendar-day][data-has-events] { font-weight: bold; }
[data-calendar-day][data-today]      { text-decoration: underline; }
[data-calendar-day][data-active]     { background: #eee; }
[data-loading]                       { opacity: 0.5; }
```

## CP Usage

Access the Calendar CP at: **Add-Ons → Calendar**

- **All Events** — list, edit, and delete events with pagination; filter by type, status and category (page links keep the filters and sort)
- **Add Event** — create a one-time event with title, description, start and end time
- **Add Recurring Event** — create a weekly event. Choose the day of the week, a **Start Date** (required), an optional **End Date**, and the start and end time. Leave End Date blank to repeat indefinitely.
- **Settings** — configure events per list count, weekly events header, and description

---

## Timezone

All event times are stored as UTC Unix timestamps. Display timezone is controlled by EE site preferences (same as EE channel entries). Configure your site timezone under **Settings → General Settings** in the EE CP.

**Recurring events repeat in site-local time.** An event entered as 6:00 PM stays at 6:00 PM on every occurrence, including after daylight saving changes. Enter recurring times in the site's local time. If you change the site time zone setting later, review your recurring events.

---

## Uninstallation

Use the EE CP to uninstall the add-on (**Add-Ons → Calendar → Uninstall**). This drops all database tables, removes the registered AJAX action, clears all caches, and deletes the `themes/user/calendar/` directory automatically.

If manual removal is ever needed, delete the `themes/user/calendar/` directory yourself — EE's uninstaller handles everything else, but the theme directory will remain if the uninstall process is interrupted or run outside the CP.

## Known Limitations

- **Recurring event dates** — a recurring event that started more than one year ago is treated as starting one year back, so calendar months older than a year show no recurring events. Recurring events saved before start dates existed (shown without a "From" date in the CP) work the same way; open one in the CP to give it a real start date.

- **Schedule list month navigation** — the `[data-calendar-event-list]` list can carry `data-calendar-list-display="none|single|recurring|both"`, which `calendar.js` uses to filter the list on month navigation independently of the calendar grid's `single=`/`recurring=`. Month navigation needs the calendar `display` tag on the page; when the calendar is hidden (`calendar_display='none'`) the Rec Room template removes the schedule's prev/next bar and the list stays static.
- **Recurring events and `{exp:event_calendar:events_list}`** — recurring events return one row per event, not one per occurrence. Events whose start date is in the future, or whose end date has passed, are not listed. Recurring rows are listed first, ordered by time of day.

- **`limit=` cache key** — the `{exp:event_calendar:events_list}` tag caches results using the limit value as part of the cache key (`calendar_events_list_{site_id}_{limit}`). If you use `limit=` to override the site default, that cache key is not automatically busted when events are created, edited, or deleted. Only the key matching the site setting default is busted. If you rely on a custom `limit=` value, you may see stale results for up to 1 hour.

- **1-hour cache staleness** — all caches have a 1-hour TTL. Events created or modified in the CP will appear on the front end within 1 hour, or immediately after the cache expires naturally.
